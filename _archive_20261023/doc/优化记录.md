本文件按**时间倒序**记录每一次策略 / 回测代码的优化：改了什么、为什么改、

## 2026-10-20 · 买入口径可实盘化：`--entry-mode confirm`（默认）

### 0. 一句话结论

旧回测 `--threshold 0.98` 的 101.67% 年化是**前视偏差**换来的：信号在窗口终点 `e`
才被 score 确认，成交却回到窗口内金叉日 `b`（`e-b` = 13~37 根，中位 **24 根**）。
新增 `--entry-mode confirm`（**默认**）后，改为确认日收盘买入、卖出计时也从 `e` 起算，
同一份数据（@0.98、K=5）年化从 **+101.67% → +0.07%**；可实盘档（@0.90 + 金叉≤5 根）
年化 **−1.14%**，仍无正期望。

### 1. 改动清单

| 文件 | 改动 |
|---|---|
| `template_scan.py` | `_trade_calc()` 新增 `entry='cross'/'confirm'`、`fresh_days`；返回 `bars_since_cross`。`entry='confirm'` 时成交日 = 窗口终点 `i1`，卖出规则（shrink/lead/bar/dif/hist0）一律从 `i1` 起算；`fresh_days>=0` 且 `i1-b > fresh_days` 时返回 `status='金叉过旧'`，由 `_scan()` 过滤并打印条数 |
| `template_scan.py` | 新增 CLI `--entry cross|confirm`（默认 **cross**，保持历史行为）、`--fresh-days`（默认 5，−1=不限） |
| `backtest_shrink.py` | 新增 `--entry-mode confirm|cross`（默认 **confirm**）、`--fresh-days`（默认 5，−1=不限）；`scan_args` 透传；`资金约束` 表新增「买入口径 / 金叉新鲜度」两行；输出名加 `_live` / `_cross` 标记；confirm 下 0 命中时提示降阈值到 0.90 |

默认值取舍：**脚本默认改为可实盘（confirm）**，`template_scan.py` 保持 cross 以兼容
`optimize_shrink.py`（后者未传 `entry`，走 `getattr` 默认值，行为不变）。

### 2. 一致性验证

1. **回归**：`--entry-mode cross --threshold 0.98` 重跑，`逐笔明细` 186 行与
   `output/backtest_shrink_all_K5.xlsx` **DataFrame.equals → True**（逐位一致）。
2. **与买点扫描对拍**：`confirm + @0.90 + fresh 5` 的 82 个窗口里，2026 年 16 笔
   买入日与 `buy_alert_hist_20260101_20261019_s0.90.xlsx` 的 17 个信号中 **16 个日期
   完全相同**；差异两处均可解释：
   * `300802` 扫描 02-10 / 回测 02-12：扫描按「同一金叉的首个新鲜日」折叠，
     回测按 `overlap=0.5` 非极大值抑制保留**最高分窗口**，两者都是合法新鲜日；
   * `600094` 未出现在回测：该笔仍 `持有中`（未触发卖出），被 `status=='已了结'` 剔除。


### 6. 结论

1. **`cross` 口径的所有绩效结论（含 N=6 最优、K 对比、年化 101.67%）都不能作为实盘预期**，
   它们共同建立在「提前 13~37 根成交」这一不可执行假设上；
2. 修正为可实盘后，该形态匹配策略在 2016-2026 全市场**没有正期望**（年化 −1.14%，
   最大回撤 −23.72%，逐笔胜率 34.2%）；
3. 后续若要做「共振确认」，应基于 `confirm` 口径继续叠加**周线/月线趋势、缩量、
   板块强度**等过滤，而不是回到 `cross` 找参数。

### 7. 遗留

* `confirm` 口径下 0.98 近乎无信号，阈值必须下探到 0.90~0.95 才有样本；
  更严阈值需要放宽模板区间或改用分段模板，否则样本量不足（0.95 档 2026 年仅个位数）。
* 卖出仍按「MACD 柱连续 6 日缩短」从确认日起算，未做 ATR/时间止损；
* `build_trades` 仍未处理卖出侧一字跌停（沿用旧局限）。

## 2026-10-19 · MACD 柱连续缩短日数 N 的定档与跨环境稳定性验证

### 0. 一句话结论

**N=6 不是最优解。** 它在「4 个环境 × 5 个指标 = 20 个判据」里一次第一都没拿到，
只是落在 N=3~8 这个「最优平台」的中间位置。真正的优选是：

| 偏好 | 推荐 N | 依据 |
|---|---|---|
| 风险调整后最优（推荐） | **N=3** | 夏普在 4 个环境里 3 次第一；Calmar 3 次第一 |
| 平衡档 | **N=4** | Calmar 在 @0.98 全市场下第一（8.38），固定夏普多环境第一 |
| 绝对收益最大（仅 @0.98 全市场） | N=7 | 年化 104.37%（固定口径 23.04%），但换池换阈值即掉出前列 |
| 现状 | N=6 | 未改动，仍是所有脚本的默认值 |

**N 默认值本次未做任何变更。**

---

### 1. 背景与起点

本次工作从一个疑问开始：`optimize_shrink.py` 的扫描表显示「N=6~9 是一档，
In/Out 比 1.08~1.14」，据此把 N 定成了 6。但那张表是**单笔统计口径**
（平均涨幅、胜率、日均涨幅），没有计入**持有时间成本**：

> 单笔涨 58% 但持有 471 天，和涨 23% 但持有 30 天，哪个好？
> 单笔统计量回答不了这个问题，只有净值级回测（年化 / 夏普 / 回撤）能回答。

因此补做了两件事：

1. 让 `backtest_shrink.py`（实盘资金约束回测）支持逐档 N 回测；
2. 补一个「永不卖出」基线，用来判断**卖出规则本身是否加分**。

---

### 2. 改动清单

#### 2.1 `backtest_shrink.py`（新建 + 本轮扩展）

新建的「金叉买入 + MACD 柱连续 N 日缩短卖出」实盘资金约束回测脚本。
核心函数：`eff_cost` / `eff_rate` / `build_trades` / `run_slots` /
`constraint_table` / `build_parser` / `main`。

本轮新增 / 变更：

| 项 | 说明 |
|---|---|
| `run_slots(..., slot_base=)` | 新增建仓基准口径：`equity` = 每笔投「当日权益 / K」（盈利复投）；`fixed` = 每笔恒投「初始资金 / K」（盈利不追加，可视为收益下界） |
| `--slot-base equity\|fixed` | 上项的开关，默认 `equity` |
| `--k-scan 3,5,8,12,20` | 一次匹配、逐 K 回测；每个 K 都跑 `equity` + `fixed` 两种口径，新增三列对照：`年化%_固定金额` / `夏普_固定金额` / `回撤%_固定金额` |
| `--include-holding` | **新增**。把「未触发卖出（持有中）」的交易也纳入回测，按该股样本末收盘价了结 = 「永不卖出」基线。没有它就算不出基线数 |
| `constraint_table` 标签 | 「已了结交易」→「参与回测交易」（基线模式下该数字含「持有中」，原名会误导） |
| 清理 | 移除未使用的 `_fee_model` import |

逐日执行顺序（`run_slots` 内部，必须保持此顺序才能同时还原资金占用与回撤）：

```
先平仓 → 重估权益 → 建仓 → 收盘重估
```

买卖成本**非对称**（含印花税），按 `eff_cost` / `eff_rate` 精确还原：
买入 ≈ 0.0260%、卖出 ≈ 0.0760%。

#### 2.2 `template_scan.py`

`--shrink-days` 默认值 **5 → 6**（含 docstring、`_trade_calc` 的 `shrink=6`）。

- `L34` docstring：「（--shrink-days 默认6）」
- `L223` `def _trade_calc(..., shrink=6, fees=None)`
- `L438` `--shrink-days ... default=6`

#### 2.3 `optimize_shrink.py`

`_scan` 的 `scan_args.shrink_days` 默认 **5 → 6**（`L141`）。

#### 2.4 `mlr/report.py`

`plot_nav()` 新增可选参数 `title`（`L172`，默认值 `'多周期共振'` 保持原样，
因此 `backtest.py` 的行为不受影响）。用于让 `backtest_shrink.py` 输出的
净值图带上各自的 K / N 标注。

#### 3.1 发现一：年化随 N 是**平滑单峰曲线**，峰顶在 N=7

```
N:    1     2     3     4     5     6     7     8     10    12    15    20
年化: 25.0  53.3  83.6  91.5  95.8  101.7 104.4 97.9  83.9  54.1  34.0  15.4
                                        ↑ 峰顶
```

曲线平滑、连续、单峰 —— 说明这不是从噪声里挑出来的孤立最优点。
「太敏感」（N=1，年化 25.0%）与「太迟钝」（N=20，年化 15.4%）都不行，
**甜区在 N=3~8**。这比 `optimize_shrink.py` 里那堆「In 净涨幅单调上升」

#### 3.2 发现二：N=0 基线年化 **0.42%**、回撤 **-55.28%**

基线占用率 92.4%、满仓天数占比 89.2%（钱几乎一直在投），**11 年下来年化仅
0.42%，回撤 -55%** —— 因为持仓全部从高点跌回来了。

**结论：卖出规则本身的价值，远大于 N 取 3 还是 7 的差异。没有它这套策略等于白干。**

| 4 | 21.80 | 11.42 | 24.44 | 23.51 |
| 5 | 22.31 | 11.88 | **25.20** | 22.98 |
| 6 | 22.74 | 12.69 | 24.50 | 23.43 |
| 7 | **23.04** | **12.92** | 23.96 | 20.81 |
| 8 | 22.85 | 12.12 | 23.05 | 20.22 |

**规律（新发现）：阈值越松 → 信号越多 → 5 个槽位竞争越激烈 → 只有小 N
（快周转）才接得住信号。** 看参与笔数就明白：

| N | 全市场@0.98 | 全市场@0.95 | 全市场@0.90 |
|---|---|---|---|
| 3 | 231 | 578 | **770** |
| 6 | 186 | 375 | 438 |
| 8 | 169 | 306 | **334** |

**N 与 threshold 不是独立参数，它们通过「槽位周转」强耦合** —— 这是上一轮
单环境扫描没能暴露出来的一层，直接决定了「不能把 N 和阈值分开调」。

#### 4.3 最优 N 总表

| 环境 | 年化% | 夏普 | Calmar | 固定年化% | 固定夏普 |
|---|---|---|---|---|---|
| 全市场@0.98 | 7 | **3** | 4 | 7 | **3** |
| 沪深300@0.98 | 7 | 4 | **3** | 7 | 4 |
| 全市场@0.95 | 5 | **3** | **3** | 5 | **3** |
| 全市场@0.90 | **3** | **3** | **3** | **3** | **3** |

**N=6 在「4 个环境 × 5 个指标 = 20 个判据」里，一次第一都没有。**
它到处都在第 2~4 名的舒适区，是**安全的中间档，不是最优解**。

### 5. 附带发现

#### 5.1 0.98 不是「筛太紧」，而是「用更少的钱赚更精致的钱」

一度以为放宽阈值更好（@0.95 的固定年化 24.96% > @0.98 的 21.05%），
但把**资金占用率**算进去就反过来了：

| 环境 / N=3 | 固定年化% | 占用率% | 每 1% 占用资金的产出 |
|---|---|---|---|
| 全市场@0.98 | 21.05 | **33.2** | **0.634** ← 最高 |
| 全市场@0.95 | 24.96 | 69.9 | 0.357 |
| 全市场@0.90 | 24.57 | 84.8 | 0.290 |

**0.98 筛出的信号质量最高（单位资金产出是 0.95 的 1.8 倍）**；放宽阈值只是
「用 2 倍的钱换 1.19 倍的收益」，边际效率递减。**所以 0.98 这个阈值是合理的，
不需要动。**

**例外**：`hs300@0.98` 的占用率只有 **8.2%~17.1%**，钱几乎全空着 —— 对沪深300
这种小池子来说 0.98 确实太严，但那是「信号数量不足」问题，不是「筛得不好」。

#### 5.2 基线（永不卖出）在**所有**环境下都 ≈ 0

| 环境 | 基线年化% | 基线夏普 | 基线回撤% | 基线占用率% |
|---|---|---|---|---|
| 全市场@0.98 | **0.42** | 0.12 | -55.28 | 92.4 |
| 全市场@0.95 | **1.52** | 0.20 | -64.79 | 95.3 |
| 全市场@0.90 | **-0.03** | 0.14 | -57.84 | **96.0** |
| 沪深300@0.98 | 9.74 | 0.52 | -44.76 | 87.1 |

全市场三个阈值下基线都在 **0 附近**，而占用率高达 92%~96%（满仓率 89%~96%）
—— 钱一直投着，11 年下来收益为零。**卖出规则的价值在四个环境里全部得到确认，
这不是巧合。**

（沪深300 基线 9.74% 高出一截，恰好说明全市场基线为什么那么低：池子里有大量
「涨上去再跌回来、不卖就套牢」的票，而沪深300 是精选大盘股、自带牛市 β。）

### 6. 已知局限（沿用上一轮，多数未解决）

1. **净值口径假设影响巨大**：全市场 @0.98 / N=6 下，`equity` 口径年化 101.67%、
   `fixed` 口径仅 22.74%，差 **4.5×**。绝大部分来自「盈利按比例复投」的复利放大
   （样本含单笔 +1737% 的暴利股）。**「K 越小年化越高」的真相是复利杠杆，不是
   资金利用率。** 因此本记录中所有结论都尽量同时给 `fixed` 口径。
2. **卖出与买入假设同日完成**：A股 T 日卖出资金 T 日可买确实成立，但 `open_open`
   模式下等于同时刻完成双向操作，现实难以达成。
3. **一字板只检查建仓价**（`backtest_shrink.py` 的 `build_trades`），**卖出侧一字
   跌停未处理** —— 实际会被砸在跌停里卖不掉。
4. **选择性偏差**：模板取自 601898 在 **2025-11-11 ~ 2026-03-16** 的上涨段，位于
   回测区间最末尾。「挑选模板」这个动作本身用了全样本信息。严格讲不是前视偏差
   （`sliding_corr` 是因果滑动），而是**选择性偏差**。
5. **`optimize_shrink.py` 的 In/Out 不是 train/test 划分**，只是按**买入日期**
   把样本劈成时间前半 / 后半做稳健性检查。
6. **流动性假设失真**：`equity` 口径后期每笔需投入巨量（100 万 → 24.4 亿，
   K=5 时每笔 4.88 亿），现实中无法成交。
7. **【本次新增】K 固定为 5 得出的全部结论。** K 变化（尤其 K=1~3，槽位更紧）
   是否会把最优 N 推向别处，**未验证**。
8. **【本次新增】N=0 基线不是「完全不操作」的干净对照**，而是「只建一次仓」：
   它的 394 笔交易持仓期全部重叠，K=5 只能接住最早的 5 笔。解读基线时必须带上
   这个前提。

### 8. 复现命令

```powershell
# ① 扫 N 档（K 固定 5），单个环境；N=0 用超大 shrink-days + --include-holding 实现
foreach ($n in 1,2,3,4,5,6,7,8,10,12,15,20) {
  python backtest_shrink.py --universe all --threshold 0.98 `
    --shrink-days $n --k-scan 5 --no-chart --out "output\_n$n.xlsx"
}
python backtest_shrink.py --universe all --threshold 0.98 `
  --shrink-days 999999 --include-holding --k-scan 5 --no-chart --out "output\_n0.xlsx"

# ② 换环境：把 --universe 换成 hs300，或把 --threshold 换成 0.95 / 0.90

# ③ 汇总：读各 _n*.xlsx 的
#    「绩效总览」第 1 行（策略行）+「资金约束」+「并发上限对比」中 K=5 那一行
```

> 汇总用的临时脚本是一次性的，未保留。三个关键 sheet 的字段名：
> - `绩效总览`：`去重交易笔数` / `年化收益(%)` / `年化波动(%)` / `夏普` /
>   `最大回撤(%)` / `Calmar` / `资金利用率(%)` / `逐笔净均(%)` / `逐笔净胜率(%)`
> - `资金约束`：`平均同时持仓(只)` / `平均资金占用率(%)` / `满仓天数占比(%)`
> - `并发上限对比`：`K(并发上限)` / `年化%_固定金额` / `夏普_固定金额` / `回撤%_固定金额`
