# 日线 MA7「上抛」扫描 —— 逻辑说明与评审

> 评审对象：`ma7_system/ma7_scan.py` 及其下游 `ma7daily/signal.py`、`ma7daily/settings.py`
> 评审日期：2026-11-02　　数据截止：2026-10-30（本地后复权缓存）
> 环境：Python 3.13.11 / pandas 3.0.5 / numpy 2.5.1
> 复现命令见文末附录；本文所有数字均可在本机复现。

## 0. 结论摘要

**整体评价**：分层干净（数据层/判定层/扫描层/回测层分离）、与主工程 `mlr` 隔离良好、
参数外置、文档与基准案例齐全，工程完成度较高。数据本身的质量很好
（709,821 行沪深300 日线中 0 重复、0 根 `high<low`、0 个非正收盘价）。

**但需要明确的定位**：当前默认口径并不是文档描述的完整形态
「下跌 → 探底走平 → 放量收复 MA7 → 沿线上抛」，而是一个
**两日触发式的「MA7 单日上拐探测器」**：

```
close > MA7  ∧  MA7[t] > MA7[t-1]  ∧  low[t] > low[t-1]
            ∧  实体阳线 ≥0.3%  ∧  收盘位于振幅上方  ∧  量 ≥0.8×前5日均量
            ∧  MA7 上行段年龄 ≤5 天
```

「下跌末端 / 探底走平 / 级别」这些前半段特征**默认全部关闭**
（`reset_lookback=0`、`reset_drawdown_pct=null`）。因此实测：

- 2020 年起沪深300 共 **18,704 个起点**（9.3 个/票/年），
  **33.9% 的股票日**处于「上抛中」，单日约出现 11～14 个新起点；
- **45.2%** 的起点当日 3 日斜率仍为负，**60.8%** 的起点 MA7 低于其自身 21 日均值，
  即多数是下跌途中的短周期拐头，而非「上抛」趋势；
- 分段中位 **7 日**，33% 的分段 ≤5 日，最长 67 日。

对盘后选股而言，这个列表是「高召回、低区分度」的候选池；
真正可操作的信息被平均掉了。**优先级最高的不是再加过滤条件，
而是把输出拆成「今日确认 / 待确认候选 / 今日退出 / 上抛中」四块，
并对同一列表做行业集中度和强度排序。**

### 需要改的 6 件事（按优先级）

| # | 问题 | 严重度 | 影响 |
|---|---|---|---|
| 1 | `--date` 历史回放有 1 日未来函数：`up`/`--recent` 会用到 D+1 的 MA7 | **P0** | 10/29 回放显示「上抛中 93」，当日实时只有 74；7/15 回放 118 vs 92 |
| 2 | 「首根上拐」名不符实：`ma_first_up` 算了但没用，`fresh_cross_days=5` 允许第 2～5 根上拐入场 | **P0（口径/文案）** | 34.4% 的起点不是首根；文档、CLI 横幅、报告三处都写「首根」 |
| 3 | `--recent` 只打印不落盘；无「待确认候选」、无「今日退出」 | **P1** | bat 声称「最近 5 个交易日」，CSV 只有当日 19 条（recent 实际 71 条）；10/30 有 33 只 raw 候选和 14 只退出完全不可见 |
| 4 | 扫描与回测退出不同构：MA 用当日 vs 前一日、成交时点不同、ABM 面板对停牌 `ffill` | **P1** | 段边界差 1～2 日；停牌股 MA7 两套口径 |
| 5 | 参数双份维护：改 `ma7.window` / `state.exit_below_days` 不会同步改回测，且无告警 | **P1** | 回测仍用 `breakdown_ma=7`、`breakdown_days=2`，静默失真 |
| 6 | 默认无级别/行业/流动性约束，单日列表行业高度集中 | **P1（策略层面）** | 10/29 的 19 只里 9 只是银行，有效独立信号只有 2～3 个 |

## 2. 端到端流程（一次日线扫描做了什么）

```
① 读参数        load_config(preset)          → DEF 深合并 ma7_daily.json（+preset）
② 选股票池      get_hs300_codes()            → 300 只（当前成分，update_date=2026-08-10）
③ 同步缓存      sync_latest_daily()          → 比对上游 backward_daily 的 MAX(trade_date)，
                                                有新数据则增量拉取并重写 parquet
④ 载入日线      load_daily(codes)            → 命中缓存则按股票切片（覆盖 ≥50% 即用）
⑤ 逐股判定      detect_frame(daily, cfg)     → 每只股票算 MA7/斜率/质量/raw/confirmed/
                                                up/entry_flag/exit_flag/seg_no/seg_len
⑥ 选交易日      last_day = --date 或数据最新日；校验必须在交易日历内
⑦ 选取 + 输出   cur = day[up]
                ent = frame[confirm_date == last_day & entry_flag]   （默认）
                recent = entry_flag & 最近 N 个交易日
                打印 + 保存 output/ma7_scan_YYYYMMDD.csv
```

一次沪深300 扫描约 **2.8 s**（其中 `detect_frame` 2.3 s，载入缓存 0.7 s）；
全市场（3,307 只 / 723 万行）约 **24.2 s**。

| 增量同步 | `mlr/data.py:287` | 以上游 `backward_daily` 的 `MAX(trade_date)` 判断是否有新数据；增量区间同时取真源表 `backward_tdx_daily` 和上游表，`keep='last'` 让真源优先 |
| 按池切片 | `mlr/data.py:57-74` | 指定 `codes` 时若缓存覆盖 ≥50% 就直接切片，缺数据的股票跳过（仅打印一行提示；本次 3 只） |

### 3.2 指标层（`signal.py:51-80`）

| 指标 | 公式 | 用途 |
|---|---|---|
| `ma7` | `SMA(close, 7)`，`min_periods=7` | 生命线 |
| `slope` | `(MA7[t]/MA7[t-k])**(1/k)-1`，默认 k=3 | 3 日复利斜率；**默认只展示**，不参与入场（`use_slope_filter=false`） |
| `slope_pct_day` | `slope*100` | 展示/退出判据 |
| `dev_pct` | `(close/MA7-1)*100` | 展示；可选 `max_dev_pct` 防追高（默认关） |
| `close_pos` | `(close-low)/(high-low)` | K 线质量：收盘位置 |
| `body_pct` | `close/open*100-100` | K 线质量：实体涨幅 |
| `vol_ratio` | `volume / mean(volume[t-5..t-1])` | K 线质量：量能（前 5 日均量，无前视） |

### 3.3 入场判据（`signal.py:106-167`）

`raw[t]` = 以下条件的**交集**：

| # | 条件 | 代码 | 默认 | 说明 |
|---|---|---|---|---|
| 1 | 指标已就绪 | `finite` | — | `ma7` 与 `slope` 均为有限值；k=3 时最早在第 10 根 bar 才可能出信号 |
| 2 | MA7 上拐 | `ma_up` | 必选 | `MA7[t] > MA7[t-1]`，**无容差**，1 分钱的上翘也算 |
| 3 | 收盘站上 MA7 | `close_above` | 开 | `close > MA7` |
| 4 | 更高低点 | `require_higher_low` | 开 | `low[t] > low[t-1]`（单日比较） |
| 5 | 斜率过滤 | `use_slope_filter` | **关** | 打开后要求 `slope >= theta(-0.05%)` |
| 6 | 实体阳线 | `bullish_only` | 开 | `close > open` |
| 7 | 实体幅度 | `min_body_pct` | 0.3% | `body_pct >= 0.3` |
| 8 | 收盘位置 | `min_close_pos` | 0.6 | 收盘在振幅上方 40% |
| 9 | 量能 | `min_vol_ratio` | 0.8 | **不是「放量」，只是「不极度缩量」** |
| 10 | 偏离上限 | `max_dev_pct` | **关** | 防追高（实测 `dev_pct` 中位 2.64%、p90 6.69%、最大 38.8%） |
| 11 | 突破新鲜度 | `fresh_cross_days` | 5 | 见下 |
| 12 | 斜率加速 | `accel` | **关** | `slope[t] > slope[t-lag]` |
| 13 | 入场前曾下行 | `reset_lookback` | **0=关** | 前 N 日内出现过 `slope < reset_slope` |
| 14 | 挖坑深度 | `reset_drawdown_pct` | **null=关** | 前 20 日 MA7 自局部高点回撤 ≥X% |

**`fresh` 的两种口径**（`signal.py:132-138`）：

- `since_turn`（默认）：`ma7_up_run` = MA7 **连续上行**已持续几天，要求 ≤5；
- `above_run`（旧口径）：收盘**连续站上 MA7** 的天数，要求 ≤5。

两者差别很大：`since_turn` 不看价格是否刚收复 MA7。实测 28,401 个起点中：
`ma7_up_run=1` 占 65.6%、2～5 占 34.4%；
`above_run=1`（当日首次站上）只占 38.5%，`above_run>5` 的还有 4.1%（最多 23 天）。
**也就是说 61.5% 的起点，前一天收盘已经在 MA7 上方**——这是「回踩后再起」，
不是「刚收复」。文档把两类都叫「起点」，但它们的形态和后续走势并不相同。

### 3.4 确认（`signal.py:170-174`）

```
next_up[t]  = ma_up[t+1]                  # 下一交易日 MA7 继续上行
confirmed[t]= raw[t] & next_up[t]
```

- 信号日仍记为 `t`；
- `confirm_date = 下一根 bar 的 trade_date`（`signal.py:267`，**是该股的下一根 bar，不一定是市场下一交易日**）；
- 实测：raw 55,000 天 → confirmed 49,088 天，**确认环节淘汰 10.7%**；
- 语义上这是一次「用未来 1 天数据做的确认」，因此信号在 `t` 收盘时**不可得**，
  最早在 `t+1` 收盘得知，最早可成交是 `t+2` 开盘。

### 3.5 状态机（`signal.py:176-223`）

```python
in_state = False; seg = 0; cur_len = 0; below = 0; slope_neg = 0; last_exit = -inf
for t in range(n):
    if in_state:
        below     = below+1     if close[t] < MA7[t]*(1-exit_below_tol) else 0
        slope_neg = slope_neg+1 if slope[t] < exit_slope_threshold      else 0
        if below >= exit_below_days or slope_neg >= exit_slope_days:
            in_state = False; exit_flag[t] = True; seg_no[t] = seg
            last_exit = t; cur_len = 0
    if not in_state and confirmed[t] and not exit_flag[t] and (t-last_exit) > cooldown:
        in_state = True; entry_flag[t] = True; seg += 1; seg_no[t] = seg; cur_len = 1
    elif in_state:
        seg_no[t] = seg; cur_len += 1
    up[t] = in_state
    seg_len[t] = cur_len if in_state else 0
```

要点：

1. **先判退出、再判入场**，同一根 bar 不会既 `exit_flag` 又 `entry_flag`；
2. 退出只计数**连续**的跌破/下弯，中间断一天就清零；
3. `up` 在**信号当日**就置 True（依赖 D+1 的确认，属于事后赋值）；
4. `exit_flag` 当日 `up=False`、`seg_len=0`，即**退出日不计入段长**；
5. `cooldown` 用 `(t - last_exit) > cooldown`，`cooldown=10` 表示退出后第 11 个交易日才可再入场。

| 功能 | 代码 | 行为 |
|---|---|---|
| 今日确认 | :95-107 | `frame[confirm_date == last_day & entry_flag]`，行日期是 **D-1**，即「昨天起点、今天确认」 |

### 3.7 配置与预设

- `settings.DEF`（:47-113）是内置默认；`config/ma7_daily.json` 覆盖；**缺项回落**；
- `--preset strict`（config:36-48）叠加三件事：
  `fresh_cross_days=3`、`reset_drawdown_pct=1.25`（20 日回看）、`cooldown_days=10`；
- 实测降噪：18,704 → **10,020**（9.30 → 4.98 个/票/年），与文档 18,676 → 10,007 基本一致
  （差异来自数据截止日）；000858 的 7/14、10/9 两个基准起点均保留；
- `validate_config`（:147-172）只做少量合法性检查，**不校验扫描/回测参数一致性**。

### 3.8 回测接口（与扫描的耦合点）

`ma7_backtest.py:143-169`：

1. `frame = detect_frame(...)` → `sig = entries(frame, start, for_trade=True)`；
2. `for_trade=True` 时 `signal_date = confirm_date`，起点日保留为 `start_date`；
3. 交给 `mlr.backtest.run` → ABM `build_trades(exec_mode='open_open')`：
   **T+1 开盘建仓**（即起点日 t 的 t+2 开盘），T+N+1 开盘平仓；
4. `exit_mode=state` 时传 `state_exit`：`{rule: breakdown, breakdown_ma: 7, breakdown_eps: 0, breakdown_days: 2}`，
   `state_horizons` 只是最长持有上限；
5. ABM 的 breakdown 用 **前一根的 MA7** 与当日收盘比较（`engine.py:232-239`），
   在第 2 根跌破日的**收盘**成交；而扫描用**当日 MA7**，状态在**次日开盘**执行；
6. ABM 面板对停牌日 `ffill`（`data.py:154-155`），但 `pos_seq` 只用真实报价日
   （`data.py:175-176`），所以不会在停牌日成交；**但 `panel.ma(7)` 含填充值**，
   与扫描「只用真实 bar」的 MA7 在停牌复牌处不一致。

### 3.9 周/月线复用

`ma7_tf_scan.py` 对每只股票 `resample_daily` 后调用同一个 `detect_frame`，
并用 `is_complete_last_bar` 区分 `confirmed / pending / forming`。
日线扫描不使用这段逻辑。

| 20 日 MA7 回撤 ≥1.25% | 13,230 | +0.58% | +1.22% | 49.0% | −0.14% |
| `dev_pct > 6` | 2,520 | +1.45% | +2.20% | 49.0% | −0.55% |

**读法**：信号有约 +1.2%/20 日的正漂移，但胜率 48.8%、中位为负，分布右偏；
`ma7_up_run=1` 略优于 2～5；**直觉上的趋势过滤（收盘>MA60/MA200、MA7 高于其 21 日均值）
在本样本内并没有更好，反而均值更低**——不能凭直觉加，必须做样本外验证。
两日延迟的成本：`t+2` 开盘相对信号日收盘平均 **+0.49%**，51.4% 的案例买得更贵。

## 5. 问题清单

### P0-1　`--date` 历史回放有 1 日未来函数

**现象**：`ma7_scan.py:86` 永远用**全样本**算 `detect_frame`，而 `entry_flag/up`
在窗口最后一天依赖 D+1 的 MA7。`--date D` 时：
- `cur = day[up]` 会把「D 日才出现、D+1 才确认」的起点算进「上抛中」；
- `--recent` 的窗口末端同样包含这些 D 日起点。

**证据**（同一份缓存，截断到 D 与不截断对比）：

| D | 回放 `up` | 当日实时 `up` | 多算 |
|---|---:|---:|---:|
| 2026-10-29 | 93 | 74 | 19 |
| 2026-10-28 | 82 | 80 | 2 |
| 2026-10-27 | 92 | 85 | 7 |
| 2026-07-14 | 100 | 79 | 21 |
| 2026-07-15 | 118 | 92 | 26（+28%） |

**影响**：仅影响历史回放/复盘（实盘扫最新日无未来 bar，是安全的），
但会让「当时的上抛宽度」「最近 N 日新起点」明显高估 20%～30%。

**建议**（一行修复）：`--date` 时先截断再判定，成本仅多 2.3 s：

```python
if args.date:
    daily = daily[daily['trade_date'] <= pd.Timestamp(args.date)]
frame = SG.detect_frame(daily, cfg)
```

### P0-2　「首根上拐」名不符实

**现象**：`ma_first_up` 在 `signal.py:94-95` 算出来但**从未使用**；入场只要求
`ma_up`（任意一天 MA7 上翘）+ `ma7_up_run <= 5`。因此第 2～5 根上拐也能入场。

**证据**：34.4% 的起点 `ma7_up_run ≥ 2`；CLI 横幅（`ma7_scan.py:57`）、
汇总文本（`report.py:39-41`）、文档多处都写「首根上拐」。

**影响**：口径描述错误。用户以为「只做第一根」，实际做的是「上行段前 5 根内的
任意上拐日」；回测报告也因此被误读。

**建议**：二选一——
1. 真要「首根」：`raw &= ma_first_up`（需重跑基准，7/14、10/9 仍是首根，不受影响；
   已核实 000400 的 2026-09-29 正是 `ma7_up_run=2`，会被这条改掉，需确认这是否是想要的）；
2. 保留现口径：把横幅/文档改成「MA7 上行段前 N 根内的上拐日」，
   并在 CSV 增加 `ma7_up_run`、`above_run` 两列（目前 CSV 有，但展示表没有）。

### P0-3　扫描与回测的退出不同构（3 处差异）

| 差异 | 扫描（`signal.py:191`） | 回测（ABM `engine.py:232-239`） |
|---|---|---|
| MA 基准 | **当日** `MA7[t]` | **前一根** `ma[prev]` |
| 退出判定日 | 第 2 根连续跌破日 | 第 2 根连续跌破日 |
| 成交时点 | 状态次日开盘（语义） | **当日收盘** |
| 停牌处理 | 只用真实 bar | 面板 `ffill` 后的 MA7（`data.py:154-155`） |

**影响**：段边界差 1～2 个交易日；停牌复牌股的 MA7 两套口径可能差很多
（复牌日扫描用「前 7 个真实 bar」，ABM 用「前 6 个填充值 + 复牌值」）。
扫描显示「已退出」而回测仍持有（或相反）会出现。

**建议**：
1. 由扫描参数派生回测配置（见 P0-4），并把 `breakdown_ma` 的比较改成
   「当日 MA」（需要在 `mlr.backtest` 层加一个开关，ABM 本身不必改）；
2. 或者在 `ma7_backtest` 里直接用 `exit_flag` 生成逐笔退出日，
   以 `exit_flag+1` 开盘价成交，彻底同构；
3. 停牌股：给 `detect_frame` 增加 `max_gap` 过滤/标记（见 P1-5）。

### P0-4　参数双份维护，改一个不会同步另一个

`ma7_daily.json` 里同时存在：

- `ma7.window` 与 `backtest.state_exit.breakdown_ma`
- `state.exit_below_days` 与 `backtest.state_exit.breakdown_days`
- `state.exit_below_tol` 与 `backtest.state_exit.breakdown_eps`

实测：把 `ma7.window` 改成 10，`state_exit.breakdown_ma` 仍是 7，
`validate_config` **无任何提示**；把 `exit_below_days` 改成 3 同理。

**建议**：`ma7_backtest.py:74-86` 改为从 `cfg['ma7']/cfg['state']` 派生，
并删除 config 里的重复项；`validate_config` 增加一致性断言（若保留两份，
不一致就报错）。

### P1-1　`--recent` 只打印不落盘

`ma7_scan.py:119-133` 的 recent 表没有写入 CSV；:135-139 只保存 `show`
（今日确认 19 条）。`run_ma7_scans.bat:21` 声明「last 5 trading days」，
但 `ma7_scan_20261030.csv` 只有 19 行、全部 `date=2026-10-29`，
而控制台 recent 有 **71 条**。

**建议**：recent 另存 `ma7_scan_recent5_20261030.csv`，或在同一 CSV 加
`bucket`（`confirmed / recent / state / candidate / exit`）列。

### P1-2　缺少「待确认候选」与「今日退出」

- 最后一天 `confirmed` 必为 False（没有 D+1），所以盘后扫描**永远看不到**
  「今天刚 raw、等明天确认」的股票。10/30 有 **33 只 raw 候选**，
  这正是次日最该盯的名单，当前完全不可见；
- 10/30 有 **14 只 `exit_flag`**，扫描也不展示，持仓跟踪缺一块。

**建议**：输出四块——
`今日确认`（可执行 D+1 开盘）、`待确认候选`（raw & ~confirmed & ~up）、
`今日退出`（exit_flag）、`上抛中`（up）。

### P1-3　`seg_len` 列在起点行恒为 1，易误读

`ma7_scan.py:131` 的 recent 表展示 `seg_len`，但起点行的 `seg_len` 是
「进入状态第 1 天」，不是「整段长度」。实测 recent 表 71 行的 `seg_len` 全是 1。
文档里的「段长 10」（7/14→7/27）也不等于 CSV 的 `seg_len`（该段 `up` 日为 9，
退出日被置 0）。

**建议**：重命名为 `seg_age`，或在 `entries()` 里 join 该段的最终长度
（`segment_len_final`，未平段标注 `open`）。

### P1-4　无数据新鲜度硬校验；DB 不可达直接崩溃

- 扫描只打印「交易日: 2026-10-30」，不校验缓存是否落后于上游/日历；
- `ma7_scan.py:83-84` 调 `D.sync_latest_daily()` 无 try/except，
  MySQL 连不上直接 traceback；`mlr/data.py:22` 顶部 `import pymysql`，
  连「只用本地缓存」也必须装 pymysql；
- `--refresh` 会强制走 DB，没有「离线只读缓存」的开关。

**建议**：`sync` 包 try/except + `--offline`；用 `cache_max` 与
「最近应有交易日」比较，落后超过 1 天时显著告警；`pymysql` 改为函数内懒加载。

### P1-5　停牌导致的「确认日」漂移

`confirm_date` 是该股的下一根 bar，不是市场下一交易日。实测 28,401 个起点中
**24 条（0.08%）** 的 `confirm_date ≠ 市场下一交易日`，最长滞后 **225 天**。
扫描的「今日确认」可能展示一个 225 天前的起点（行日期很旧），视觉上很突兀。

**建议**：`confirm_gap = 市场交易日序号差`；超过阈值（如 5）标记
`stale_signal` 并在展示/回测中排除或单列。

### P1-6　无盘中/未收盘保护

日线扫描直接取缓存最后一根 bar，不判断它是否是完整收盘日；
`ma7_tf_scan` 有 `is_complete_last_bar`，日线没有。若在盘中运行，
或上游写入当日未收盘行，就会把半根 K 线当收盘。

**建议**：加 `--allow-partial`；默认在「最后一根 == 今天且当前时间 < 15:00」
时告警或拒绝，除非显式允许。

### P1-7　股票池幸存者偏差

`config/hs300_constituents.json` 是 **2026-08-10** 的当前成分。回测 2020 年起
用当前成分 → 存活偏差；`mlr/universe.py:14-17` 已写明，但扫描 CSV 和回测报告
都没有显著标注。

**建议**：CSV 增加 `universe_update_date`；回测汇总首行加警告；
有条件时接历史成分股。

### P1-8　单日列表行业高度集中，缺少排序

10/29 的 19 只里有 **9 只银行**（平安、宁波、招商、江苏、杭州、南京、邮储、成都、中信），
另有中国石化、中国神华、兖矿等资源股；按等权理解，这其实是 2～3 个行业押注，
不是 19 个独立机会。

**建议**：输出增加行业（或至少名字前缀分组）计数；按 `freshness / 量比 / 斜率 /
dev` 给一个可解释的排序分；或提供 `--max-per-industry` 截断。

### P2-1　K 线质量阈值是「保 4 个样本」反推的

`min_body_pct=0.3`、`min_vol_ratio=0.8` 明确是为了容纳 7/14（量比 0.84）和
10/9（实体 0.39%）；`validate_config:169-171` 还把 `reset_drawdown_pct`
上限定死 1.5%，以免滤掉 10/9（1.54%）。这是样本内拟合，不是通用约束。

**建议**：把 1.5% 从「校验错误」降级为文档提示；参数选择做分年份/walk-forward
稳定性检验，别用 4 个案例同时做「调参」和「验收」。

### P2-2　`exit_slope` 规则几乎不生效

28,322 次退出中只有 **111 次（0.4%）** 由斜率触发，其余都是连续 2 日收盘 < MA7。
回测也没有建模这条规则（`report.py:45-47` 自己承认）。
它是一个增加复杂度、几乎不改变结果的参数。

**建议**：删除，或调阈值让它有实际作用，并与回测统一。

### P2-3　死代码/未接线参数

- `persist`：读了但从未使用（`signal.py:41`）；
- `entry_backdate`：从未读取；
- `ma_first_up`：算了不用；
- `theta`：只在 `use_slope_filter=true` 时生效，默认关；
- `use_slope_filter=False` 时 CLI 仍打印「突破 N 日内」，但不提斜率过滤已关闭。

**建议**：清理或接线；`validate_config` 对「配置了但不会生效」的项给出提示。

### P2-4　`validate_config` 覆盖不足

未检查：`ma7.window` 与 `breakdown_ma` 一致、`exit_below_tol` 与
`breakdown_eps` 一致、`fresh_mode` 拼写错误（`_detect_one` 会静默按
`since_turn` 处理）、`min_*` 依赖的 `open/high/low/volume` 列是否存在。

**建议**：补上这些交叉校验；对未知 `fresh_mode` 直接报错而不是静默。

### P2-5　周/月线的「完整周期」判断在长假周误判

`ma7_tf.py:60-65` 用「下一个工作日是否跨周期」判断：
2026-09-30（周三，国庆前最后交易日）和 2026-04-30（周四，五一前最后交易日）
都被判为「未完成」，导致已收盘的周被当成进行中，周线信号延后一周。
日线扫描不受影响，但 README「周/月线与日线同一套逻辑」的说法需要修正。

**建议**：用交易日历判断「该股/市场下一交易日是否跨周期」，而不是 `BDay`。

### P2-6　无回归测试、无可复现元数据

**建议**：加 `pytest`（黄金文件断言上述日期）；写
`ma7_scan_<date>.meta.json`（配置子集 + 计数 + 数据区间 + 池版本）。

## 6. 改进路线（建议按批次做）

### 批次 A：盘后工作流（半天，收益最大）

1. 扫描输出拆四块：`今日确认 / 待确认候选 / 今日退出 / 上抛中`；
2. `--recent` 落盘 + `scan_date` 列；
3. `--date` 先截断再判定（修 P0-1）；
4. 写 `meta.json`（preset、参数、数据区间、池版本、计数）。

### 批次 B：口径一致性（1 天）

1. 回测 `state_exit` 从 `ma7/state` 派生，删除重复配置（P0-4）；
2. 统一退出语义：`exit_flag` 驱动回测，或给 `mlr.backtest` 加「当日 MA / 前一日 MA」开关（P0-3）；
3. 停牌：`confirm_gap` 标记 + `max_gap` 过滤（P1-5）；
4. 数据新鲜度/离线/DB 容错（P1-4）；
5. 盘中保护（P1-6）。

### 批次 C：策略研究（需要样本外）

1. 分级：A 级（前期 MA7 回撤 ≥X% + 首根 + 量比 ≥1.2 + 收盘 > MA21）、B 级（其余）；
2. 行业/流动性约束与排序分；
3. walk-forward：2015-2019 调参、2020-2022 验证、2023-2026 再验证；
4. 不要直接加「收盘>MA60/MA200」这类直觉过滤——本次样本内它们更差（见 4.4）。

### 不建议改的

- `fresh_mode=since_turn` 本身是对的（`above_run` 会让段内回踩反复重生起点）；
- 连续 2 日跌破才退出是对的（单日回踩很常见）；
- `open_open` + 确认日期的回测口径是对的（虽然比「信号日叙事」晚 2 天）；
- 数据层（`mlr.data`）质量很好，不需要动。

本文用到的关键复现脚本（临时目录，可另存）：

```python
# ma7_eval.py 的核心
from ma7daily import settings as S, signal as SG
from mlr import data as D, universe as U
codes, _ = U.get_hs300_codes()
daily = D.load_daily(codes=codes, verbose=False)
f = SG.detect_frame(daily, S.load_config()).sort_values(['stock_code', 'trade_date'])
g = f.groupby('stock_code', sort=False)
for H in (10, 20):
    f[f'fwd{H}'] = g['open_price'].shift(-(2 + H)) / g['open_price'].shift(-2) - 1
e = f[(f.entry_flag) & (f.trade_date >= '2020-01-01')]
print(e[['fwd10', 'fwd20']].describe())
```

**数据与口径备注**

- 价格为本地**后复权**缓存，绝对值与行情软件前复权不同，形态/斜率/偏离一致；
- 前向收益为**重叠样本、无成本、t+2 开盘买**，只用于横向比较，不是策略净值；
- 所有计数以 2026-10-30 缓存为准；文档中的 18,676/10,007 对应更早的数据截止日，
  复现值为 18,704/10,020，差异属正常。
