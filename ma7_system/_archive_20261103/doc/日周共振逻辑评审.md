## 1. 冻结版规则的形式化（我按这个复现）

### 1.1 周线：斜率段 → 上抛区间

```text
周线 K 线      W-FRI 重采样，period_date = 该周最后一个交易日
MA7w           7 周 SMA(收盘)
s5w            (MA7w[t] / MA7w[t-5]) ** (1/5) - 1

斜率段  pos[t] = s5w[t] > 0
        起点  = 连续 2 周 pos（且前一周不为正）
        持续  = pos 为真，允许 1 周回踩（gap < 1）
        终点  = 连续 2 周 pos 为假，段尾 = 最后一个 pos 为真的周

区间    起点 = 段内【首次】收盘 > MA7w 的那一周 s0
        终点 = 从 s0 起【连续 3 周】收盘 < MA7w，第 3 周 e 即「结束确认周」
        区间 = [s0, e]（含端点）
        同一斜率段内若跌破 3 周后重新站上 → 切分成第二段区间（不合并）
```

### 1.2 日线：斜率段 → C / B → 确认

```text
s5[t] = (MA7[t]/MA7[t-5])**(1/5)-1
段    = 同上（连续 2 天起点、允许 1 天回踩、连续 2 天结束）
C     = 段内首次收盘 > MA7 的那天才算起点 s0；s0..s0+2 三连收盘 > MA7 → 第 3 天确认
B     = 前一日收盘 < MA7、当日重新站上，且当日..+2 三连 > MA7 → 第 3 天确认
方案3 = C 一次 + 每一次 B 都给信号（这是冻结版 §2 的新增点）
确认  = 3 天窗口的第 3 天收盘
开仓  = 确认日的下一个交易日开盘
```

### 1.3 共振与平仓

```text
共振   weekly_start <= 日线确认日 <= weekly_end，否则不开仓
平仓   连续 3 个交易日收盘 < 日线 MA7 → 次日开盘平仓
       数据末端未触发 → 按最后一根收盘计（未平仓）
成本   0.2% 双边
```

时序上两层都是「事后确认」：

```text
周线：第 W 周收盘站上周 MA7 ──► 区间从 W 起（周末才可知）
日线：第 D 天三连站上 ──► D 收盘确认 ──► D+1 开盘买
平仓：连续 3 天跌破 ──► 第 3 天收盘确认 ──► 次日开盘卖
```

### 1.4 参数对照：文档 vs 代码

| 项 | 冻结版 | 代码/配置现状 |
|---|---|---|
| 日线 MA7 | 7 日 SMA | `ma7.window=7` ✅ |
| 斜率窗口 | 5 | `segment.slope_window=5` ✅ |
| 日线段起止 | 2 天确认、允许 1 天回踩 | `start_confirm=2, end_confirm=2` ✅ |
| 信号根数 | 3 连收盘 > MA7 | `signal.close_above_days=3` ✅ |
| 多信号 | 每段 C 一次 + 每次 B（方案 3） | ❌ 每段一个（C 优先、B 兜底） |
| 周线 MA7 / s5w / 区间 | 冻结版 §1 | ❌ 无代码，只有临时脚本产物 |
| 共振匹配 | 确认日 ∈ 区间 | ❌ 无代码 |
| 平仓 | 连续 3 日跌破 → 次日开盘 | ❌ 无代码；旧状态机是 `exit_below_days=2` |
| 成本 | 0.2% 双边 | `backtest.cost=0.002` ✅ |

**这张表最关键的一行是「周线区间」和「共振匹配」：整条链路没有可执行代码。**

- **闸门没有筛出更好的信号**：区间内 20 日 +1.04%，比区间外低 0.47pp，胜率也低 5pp。

- **方案 3 vs 每段单信号**：均值 +0.53% vs +0.50%，胜率相同 —— 多出来的 45% 信号只是增加频率，单笔质量没有变化。
- **周线闸门 vs 不加闸门**：均值 +0.53% vs +0.55%，胜率 34.5% vs 35.1% —— 闸门把笔数砍掉一半，单笔期望反而略低。

| 2025 | 1,272 / +1,960 | 2,453 / +2,721 |
| 2026 | 634 / −98 | 1,633 / −151 |

- 2016/2018 两个熊市年，闸门确实把亏损砍了一半（−310 vs −590、−1,114 vs −2,813）；
- 但 2017/2019/2020/2025 的牛市年，闸门也把利润砍了一半；
- 2022、2024 年闸门反而更差。

→ **闸门的作用是「减仓」而不是「择时」**：它没有提高单笔质量，只是让交易频率减半、暴露减半。

### 4.5 这些数的边界（不要直接当策略结论）

1. **幸存者偏差**：股票池是 2026-08-10 的沪深300 快照，历史上退市/被调出的票不在样本里。
2. **单一离场**：只测了「连续 3 日跌破」；换离场（2 日、周线结束、固定持有）结论可能变。
3. **收益和不是净值**：+5,535pp 是 10,466 笔百分比相加，不能当组合收益读。
4. **未扣涨跌停/停牌**：次日开盘价在实盘可能买不到。
5. 20 日前向收益是**描述性**指标，不是策略收益。

## 5. 逻辑问题清单

### P0-1　方案 3 只存在于文档

`ma7daily/upthrow.py` L156-L172：C 成功就 `elif fb` 不执行；B 循环里 `break` 只取最早一个；
每段扫完 `i = last + 1` 不再回头。`ma7_scan_close3.py` 的 docstring 也明写「每段只取最早的一次」。

后果：
- 现在跑扫描得到的是 33 笔口径（`dw_resonance_entries.csv`），不是冻结版的 46 笔；
- 全样本差 45% 的信号，单票最多差 13 笔；
- 没有任何配置项能切到方案 3（`config/ma7_close3.json` 只有 `fallback_reclaim/fallback_min_dip`）。

**要么改代码（新增 `signal.multi_reclaim=true`），要么在冻结版里明确「方案 3 暂不实现、以单信号为准」。现在两存。**

### P0-2　「单仓」是隐含规则，且与冻结版冲突

冻结版 §3 只说「在区间内 → 开仓」。参考输出实际按「持仓中忽略新信号」（否则 600188 是 59 笔，不是 46 笔；
全样本 13,742 个共振信号只成交 10,466 笔）。这条规则至少决定三件事：

1. 同一票并发几个仓位；
2. 新信号来了是加仓、替换（强弱切换）还是忽略；
3. §6 示例表到底列 4 笔还是 6 笔。

**必须先写进冻结版，否则扫描 CLI 没法实现、回测没法复现。**

### P0-3　区间尾部 3 周仍在开仓

区间终点是「连续 3 周跌破」的第 3 周，所以周线在第 1、2 周跌破时，区间仍然有效。
因果口径下，区间内 5.5% 的信号（759 个）发生在「最后一个已收盘周已经跌破周 MA7」之后，
20 日 −0.08%，其余 +1.10%。若按当周收盘算（事后），比例升到 11.9%、20 日 −3.17%。

这直接违背 §1 的语义（「周线上抛区间」），也是全样本里唯一稳定为负的分组。
**建议：区间终点改为「首次跌破周」（或至少要求确认日 <= 最后站上周），不要留 3 周宽限。**

### P1-1　C 不是「首次站上」（86.2%）

因为斜率段的起点是「MA7 连续 2 天斜率 > 0」，而 MA7 转正通常发生在价格已经站上 MA7 之后，
所以「段内首个收盘 > MA7」绝大多数时候**不是新突破**，只是段起点那根（价格早就在上方）。

实测：C 信号 17,831 个，其中 15,378 个（86.2%）在段起点前一日收盘已在 MA7 上方。

后果：
- 同一轮上涨里斜率段一重启就给一次 C → 信号密度 9.2 个/票/年；
- 「C 是主信号、B 是兜底」的表述与实际分布不符（C 17,831 个、B 约 1.19 万个，B 占 40%）；
- 旧文档里 `fresh_cross_days` 想压制的「趋势中继里反复重生起点」，在这里又回来了。

**建议：C 增加「前一日收盘 < MA7」（真正的首次站上）；否则把它改名为「段内首根站上」。**

### P1-2　区间定义与「周线上行」不等价（两个方向都拧了）

- **该收的没收**：周线收盘 > MA7 但 s5w 还没转正（最早的反转段）被排除在区间外，
  而这组信号 20 日 +1.72%，是全样本最好的一段；
- **不该收的收了**：跌破后 3 周宽限期内的信号被收进来（−0.08%）。

也就是说，区间既不是「周线在 MA7 上方」的超集，也不是子集，而是一个交错的集合。
如果目标是「只做周线上行」，最直接的做法是**直接用周线状态**（收盘 > MA7 且 s5w > 0，按最后一个已收盘周判定），
而不是这个复合区间。

### P1-3　密度 / 排序 / 并发上限

3.3 笔/票/年 × 300 票 ≈ 1,000 笔/年；单仓 + 次日开盘，实盘资金接不住。
冻结版没有任何排序规则（周线强度、区间剩余周数、距 MA7 距离、成交量），也没有并发上限。
`ma7_backtest.py` 里有 `concurrent_cap`，但共振链路没接。

### P2-1　参数表日/周混用

§5 的「段起点确认 2 / 段终点确认 2（允许 1 天回踩）」是**日线**口径；周线口径只在 §1 正文里（2 周、1 周回踩）。
「周线结束跌破周数 3」又是**区间**口径，不是段口径。三个东西分属两层，表里并排容易被当成同一套。
**建议参数表按「日线 / 周线 / 共振」三块重排。**

### P2-2　ongoing 区间、停牌、长假、未收盘

- 数据末端「进行中」区间（000400 2026-10-30 起）怎么处理，冻结版没写；
- 停牌导致 `entry_date` 是下一根 K 线而非「次日」，与 §2「下一个交易日开盘」有出入；
- W-FRI 重采样在长假周/停牌周，`period_date` 可能不是周五，区间端点用「周五」还是「该周最后交易日」未规定；
- 盘中扫描时当周 K 线未收盘，周线 MA7 是半成品 —— 必须规定「周线只用已收盘周」。

### P2-3　窄口径未来函数（2.43%）

区间起点 = 段内首次站上周，而段起点需要「连续 2 周 s5w > 0」才成立。
若首次站上周就是段的第一周，那么这一周收盘时段的资格还没被下一周确认。
实测 13,748 个区间内信号里，334 个（2.43%）正好落在「区间起点 = 段起点」的那一天。
影响不大，但实盘按此规则会「当时不开、事后算开」。

### P2-4　三套输出无口径标注；「净收益」列易误读

- 33 / 59 / 46 三个 CSV 没有任何 meta 标注规则开关（是否方案 3、是否单仓、几日落袋）；
- `opt3_exit3.csv` 的「净收益」是单笔百分比，46 笔相加 ≈ −25.5pp，不是净值；
  §6 表里的 +18.6% / −7.5% 也会被误读成策略收益。

### P2-5　没有脚本、没有回归

周线区间 + 共振匹配只在已删除的临时脚本里；现在能跑的只有 33 笔口径。
**没有 golden case 就无法防止下次改规则时静默漂移。**

## 附录 B　核心实现（可直接运行）

```python
import numpy as np, pandas as pd, sys
sys.path.insert(0, r'F:\ai_multi_level_resonance')
from mlr import data as D

WIN, K, SC, EC, NEED = 7, 5, 2, 2, 3

def weekly(daily):
    g = daily.sort_values('trade_date').set_index('trade_date')
    r = g.resample('W-FRI')
    w = pd.DataFrame({'close': r['close_price'].last()}).dropna()
    w['period_date'] = g.index.to_series().groupby(pd.Grouper(freq='W-FRI')).last().reindex(w.index)
    return w.reset_index(drop=True)

def segments(pos):
    n, out, i = len(pos), [], 0
    while i < n - 1:
        if pos[i] and (i == 0 or not pos[i-1]) and np.all(pos[i:i+SC]):
            st, last, j, gap = i, i + SC - 1, i + SC - 1, 0
            while j + 1 < n:
                if pos[j+1]: gap, last, j = 0, j + 1, j + 1
                elif gap < EC - 1: gap, j = gap + 1, j + 1
                else: break
            out.append((st, last)); i = last + 1
        else: i += 1
    return out

def intervals(w):
    c = w['close']; ma = c.rolling(WIN, min_periods=WIN).mean()
    pos = ((ma / ma.shift(K)) ** (1.0/K) - 1 > 0).to_numpy()
    above = (c > ma).to_numpy(); n = len(w); rows, cur = [], 0
    for st, last in segments(pos):
        cur = max(st, cur)
        while cur <= last:
            idx = np.flatnonzero(above[cur:last+1])
            if not len(idx): break
            s0 = cur + idx[0]; run = 0; e = None
            for t in range(s0, n):
                run = run + 1 if not above[t] else 0
                if run >= 3: e = t; break
            if e is None: e = n - 1
            rows.append((s0, e)); cur = e + 1
    return rows, above, ma.to_numpy()

def signals(df):
    c = df['close_price'].to_numpy(float)
    ma = pd.Series(c).rolling(WIN, min_periods=WIN).mean().to_numpy()
    s5 = ((pd.Series(c).rolling(WIN, min_periods=WIN).mean() / pd.Series(c).rolling(WIN, min_periods=WIN).mean().shift(K)) ** (1.0/K) - 1) * 100
    pos = (s5 > 0).to_numpy(); above = c > ma
    out = []
    for st, last in segments(pos):
        idx = np.flatnonzero(above[st:last+1])
        if not len(idx): continue
        s0 = st + idx[0]
        if s0 + NEED - 1 <= last and above[s0:s0+NEED].all():
            out.append((s0, s0+NEED-1, 'C'))
        for t in range(s0+1, last-NEED+2):          # 方案3：每个 B 都给
            if above[t] and not above[t-1] and above[t:t+NEED].all():
                out.append((t, t+NEED-1, 'B'))
    return out, above
```

（`weekly / intervals / signals` 三个函数 + 单仓 + 3 日跌破，即可复现本文全部数字。）
